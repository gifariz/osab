# OSAB model format (JSON)

One file holds a whole model: an `.osab` file, JSON (UTF-8) inside. The app and `osab solve` also
read the same content from a `.json` file (models saved before 2026-11-11 were `.json`). Units must be consistent (the file only records which ones you used). The app always
writes kN and m and only shows them in other units (`gui.units`, see below).
Example: [examples/portal_frame.osab](../examples/portal_frame.osab).

**Objects and elements.** The file holds *objects*: what you draw (joints, frames, links,
areas). The solver analyses *elements*. Running a model first calls the **mesh step** (crate `mesh/`,
PHASE3B_PLAN.md), which, like auto-mesh, splits areas into 3- and 4-node shell
elements (`F1-1, F1-2…`), adds mesh joints (`~1, ~2…`), splits frames at the joints along them
(`B1-1…`) and ties joints that lie on element edges (edge constraints); null objects (no section) and
joints with nothing attached get no elements, their loads going to the elements under them; then the
solver analyses that model. Results report frames per frame object and shells per element with their `area`. Where a frame
(or an edge constraint) meets a wall element at a corner, the solver adds a frame-to-wall spring
(`solver/src/elements/wall_joint.rs`); there is
nothing to set for it.

```json
{
  "title": "Portal frame",
  "dimension": "2D",
  "units": { "force": "kN", "length": "m" },
  "materials": [ { "id": "steel", "E": 200e6, "nu": 0.3 } ],
  "sections":  [ { "id": "COL", "A": 0.012, "I22": 5e-5, "I33": 1.5e-4, "J": 2e-6 } ],
  "nodes":     [ { "id": "1", "x": 0, "y": 0, "z": 0 }, { "id": "2", "x": 0, "y": 0, "z": 4 } ],
  "frames":    [ { "id": "1", "type": "frame", "nodes": ["1", "2"], "material": "steel", "section": "COL" } ],
  "supports":  [ { "node": "1", "fix": "fixed" } ],
  "load_patterns": [
    { "id": "WIND", "type": "wind", "node_loads": [ { "node": "2", "fx": 10 } ] },
    { "id": "DEAD", "type": "dead", "frame_loads": [ { "type": "uniform", "frame": "1", "dir": "Z", "w": -15 } ] }
  ],
  "load_cases": [
    { "id": "WIND", "loads": [ { "pattern": "WIND", "scale": 1 } ] },
    { "id": "DEAD", "loads": [ { "pattern": "DEAD", "scale": 1 } ] },
    { "id": "ULS", "loads": [ { "pattern": "DEAD", "scale": 1.2 }, { "pattern": "WIND", "scale": 1.6 } ] }
  ]
}
```

## Fields
| Field | Meaning |
|---|---|
| `version` | The **file format version**, a whole number: `1` now. The app writes it on every save; a file without it is an older one and opens as before. A file with a higher number than this OSAB knows was made by a newer OSAB and is refused with a message saying so (see *File format version* below). |
| `dimension` | `"3D"` (default), `"2D"` (the app's *Analysis Options > Plane frame in X-Z*) or `"grid"` (*Plane grid in X-Y*). A 2D model lies in the global X-Z plane: all nodes need the same y, UY, RX and RZ are restrained at every node, and out-of-plane loads (fy, mx, mz, or frame loads with a Y part) are rejected. A plane grid (a floor with its beams) lies in one X-Y plane: all nodes need the same z, UX, UY and RZ are restrained at every node (so only UZ, RX and RY act: plate bending, beam bending about horizontal axes and torsion), and loads in the plane (fx, fy, mz, frame or area loads with an X or Y part) are rejected. A flat floor's bending does not depend on its in-plane part, so a grid gives the same values as the 3D run of the same model (B37, `mesh/tests/plane_grid.rs`); equivalent is the active DOFs UZ, RX, RY. |
| `materials` | `E`, and `G` or `nu` (G = E / 2(1 + nu)); optional `weight`, the weight per unit volume (force / length³, missing = 0) for self-weight. Optional `type`: `"steel"` (with optional strengths `fy`, `fu`), `"concrete"` (`fc`, f'c) or `"other"` (no strengths); stresses in force / length². The type and strengths are kept with the model and change no result. Missing `type` (files before 2026-11-06): steel if E is 150 GPa or more, concrete from 10 to 60 GPa, else other. |
| `sections` | `A`, `I22`, `I33`, `J`, optional shear areas `As2`, `As3`. A shear area of 0 or missing = no shear deformation in that plane. Trusses only need `A`. Optional `depth` and `width` (t3 along local 2 and t2 along local 3): the automatic end offsets and the cardinal points use them. Optional `I23` (product of inertia ∫ x2 x3 dA: the member bends about its principal axes; I23² < I22 I33; end releases must free both V2 and V3 or neither, both M2 and M3 or neither), `centroid_offset` and `shear_centre_offset` ([along 2, along 3] from the middle of the box: cardinal points 1-9 and 11), `self_weight` (force per length, replacing material weight x A: composite sections). |
| `sections[].shape` | Optional. The shape a section is made from; the mesh step works out `A`, `I22`, `I33`, `I23`, `J`, `As2`, `As3`, `depth`, `width`, `centroid_offset` and `self_weight` from it (they may then be left out). `{"type": ...}` with lengths in the model's unit: `rectangle` (depth, width), `i` (depth, width, flange, web, optional bottom_width, bottom_flange), `channel` (depth, width, flange, web, mirror: web on -3), `tee` (depth, width, flange, web, mirror: flange at the bottom), `angle` (depth = vertical leg, width = horizontal leg, flange = its thickness, web = the vertical leg's, mirror2, mirror3), `double_angle` and `double_channel` (width = the whole width, gap), `box` (depth, width, flange, web), `pipe` (diameter, wall), `circle` (diameter), `concrete_tee` (web at the flange, web_tip), `concrete_l` (web at the corner, web_tip, mirror2, mirror3), `concrete_pipe`, `cross` (flange = the horizontal bar, web = the vertical bar), `trapezoid` (width at the top, bottom_width), composite `filled_tube`, `filled_pipe` (material = the steel, fill), `encased_rectangle`, `encased_circle` (core = an `i` shape, material, encasement), and `aisc` (name = an AISC Shapes Database v16.0 label such as `W14X90`, `L6X4X1/2`, `2L6X4X1/2LLBB`, `HSS20X12X5/8`, `Pipe8XS`: A, I and J as tabulated, converted to the model's length unit; `like`, written by the app, only draws it). B66. A composite section is transformed to `material`; its frames must have that material. B65. |
| `sections[].modifiers`, `frames[].modifiers` | Optional. Frame **property modifiers**: `{"A": 0.8, "As2": 1, "As3": 1, "J": 0.25, "I22": 0.7, "I33": 0.7, "mass": 1, "weight": 1}` (missing = 1). Each scales its own section value; a frame is analysed with its section's modifiers times its own (Phase 4 probe findings 1b, B44). Stiffness values must be > 0; `mass` and `weight` >= 0 (`weight` scales self-weight, `mass` the element mass of a modal case). |
| `nodes` | `x`, `y`, `z` (missing = 0). Ids can be numbers or text. |
| `nodes[].in_mesh` | *Include in mesh* (mesh step). Only matters for a joint with nothing attached (no frame, area corner, link, support or spring), e.g. one that only carries a joint load: missing or `false` leaves it out of the mesh (the default), and its joint loads (all six components) go to the joints of the floor or wall element it lies in, by that element's shape functions at the joint; it reports no displacement. `true` makes it a mesh joint (in a Rectangular floor its lines are kept like a column's). |
| `nodes[].special` | *Special joint*: `true` keeps the joint when the objects attached to it are deleted or moved away; missing = no (such a joint is deleted when an edit leaves it with nothing attached). Joints drawn on their own are special. The analysis ignores it. |
| `frames` | Frame objects: `type` `"frame"` or `"truss"`, two `nodes` (end i, end j), `material`, `section`, optional `angle` (degrees). Files written before Phase 3a call this list `elements`; they still open. |
| `frames[].releases` | Optional. **End releases**: `{"i": ["M2", "M3"], "j": ["M3"]}`, the end forces (`P`, `V2`, `V3`, `T`, `M2`, `M3`, local axes) that are zero at end i and end j (end order: a frame given the other way round has its releases swapped with its ends). Solved exactly by static condensation; the member's own end rotations at a release are reported in its deflected shape. Refused: P, V2, V3 or T released at both ends, M3 at both ends with V2 at an end, M2 at both ends with V3 at an end, and releases on a truss. When the mesh step splits a frame, only its own two ends keep the releases. Partial fixity springs are not supported. On a member with end offsets the releases act at the clear-length ends, and the whole offset at a released end is rigid whatever `rigid_zone` (B48 D, B54). |
| `frames[].end_offsets`, `frames[].rigid_zone` | Optional. **End length offsets**: `"auto"` (*Automatic from Connectivity*: a beam end gets (t3/2) cos²θ + (t2/2) sin²θ of the column ending below it, θ between the beam and the column's local 2 axis; a column top the largest beam depth there × max(cos²θ, sin²θ); column bottoms, braces and trusses 0) or given lengths `{"i": 0.4, "j": 0.4}` at end i and end j (swapped with the ends for the end order; together less than the length). `rigid_zone` (0 to 1, missing = 0) is the part of each offset that is rigid in bending and shear; axial and torsion act over the whole length, loads on a rigid part go to its joint, and frame forces are reported over the clear length between the offsets. With self-weight, beams weigh over their clear length. When the mesh step splits a frame, each piece gets the part of the offsets on it. New frames drawn in the app get `"auto"` (B48, B49). |
| `frames[].insertion` | Optional. **Insertion point**: `{"point": 8, "mirror2": false, "mirror3": false, "offset_i": [0, 0, 0], "offset_j": [0, 0, -0.2], "global": false, "transform": false}`, every key optional (missing = point 10, nothing else). `point` is the cardinal point on the box around the section in its local 2-3 plane (sections give `depth` along 2 and `width` along 3): 1 bottom left, 2 bottom centre, 3 bottom right, 4 to 6 middle, 7 to 9 top (bottom = the -2 face, left = the -3 side), 10 centroid, 11 shear centre (the centroid of the doubly symmetric sections here). `mirror2` / `mirror3` mirror the section about local 2 / 3 (the cardinal point flips to the other side). `offset_i`, `offset_j`: joint offsets from each joint to the cardinal point, in local 1, 2, 3 or (with `global`) X, Y, Z; swapped with the ends for the end order (a local offset along 1 changes sign). With `transform` the element runs between the section's centroids and rigid arms tie its ends to the joints: frame forces are those on the element's own axis, loads act on that axis, releases at its ends; without it (the default, and what the app draws) the insertion point only moves the drawing. When the mesh step splits a frame, joint offsets along it follow a straight line from end i to end j (a local offset along 1 stays at the frame's own ends). Automatic end offsets and the element mass do not depend on it (the mass stays at the joints, half to each end, with no rotational part). |
| `frames[]` without `section` | A **null frame** (section "None"; no `material` needed): no stiffness and no element. Floors are meshed along it (in a Rectangular floor its end j, by the end order, keeps its lines like a column's, its end i gets local lines). Its frame loads go to the floor elements it lies on (the load times their shape functions along the line); a part over no floor is lost. Null frames have no results. |
| `frames` (crossings) | The mesh step splits frames where they cross: two frames passing within 1 mm of each other (in the model's length unit) are both split and joined at the point on the one that comes first; a frame passing within 1 mm of an area's edge is split there and tied to the edge when within 0.1 mm of it. Null frames and areas split nothing. |
| `frames[].in_mesh` | *Include in mesh* for frames. Missing = yes (*Program Determined*): floors are meshed along the frame. `false`: the floor is meshed as if the frame were not there, and the frame is split where it crosses element edges and tied to them there (edge constraints), e.g. a stiffener that should not carry the floor's gravity load directly. |
| `supports` | `fix`: `"fixed"`, `"pinned"` (ux, uy, uz) or a list such as `["ux", "uz", "ry"]`. |
| `springs` | Optional. Joint springs in global axes, one entry per joint: `{"node": "1", "ux": 50000, "ry": 20000}`. `ux uy uz` in force/length, `rx ry rz` in force·length/radian; missing = 0, values >= 0. A spring on a restrained DOF has no effect (the DOF cannot move; a note says so). |
| `line_spring_props`, `frames[].line_spring` | Optional. **Line springs**: properties `{"id": "LS1", "u1": 0, "u2": 5000, "u3": 0, "r1": 0}`, stiffness per unit length along the frame's local 1, 2, 3 (force/length²) and about local 1 (force·length/radian per length), missing = 0, values >= 0; a frame names one with `"line_spring": "LS1"`. Lumped at the joints of each frame element: each end gets the stiffness times half the element's length, in the element's local axes (an unmeshed frame has it at its two ends only; the pieces the mesh step makes each get theirs). They act at the joints (not at an insertion point) and their forces are in the joints' reactions. Linear only. |
| `area_spring_props`, `areas[].area_spring` | Optional. **Area springs**: properties `{"id": "AS1", "u1": 0, "u2": 0, "u3": 20000}`, stiffness per unit area along the area's local 1, 2, 3 (force/length³; `u3` is a floor's subgrade modulus), missing = 0, values >= 0; an area names one with `"area_spring": "AS1"` (not openings). Lumped at the corners of each shell element: each corner gets the stiffness times its share of the element, the integral of its shape function (the share of a uniform area load: A/4 on a square, A/3 on a triangle), in the element's local axes; the mesh step gives the area's spring to its elements. They act at the joints and their forces are in the joints' reactions. Linear only. |
| `links` | Optional. Rigid links: `{"id": "L1", "type": "rigid", "nodes": ["2", "5"]}`. The two joints move as one rigid body (all six DOFs). Joints joined by links form a rigid body; one joint (the restrained one, else the first in the file) is its master and the others follow it exactly (master/slave constraint, no stiff numbers). Rules: two different joints at different points; ids differ from frame ids; links must not form a closed loop (remove one link: the body stays rigid); at most one joint of a rigid body may have restraints. Springs and loads may be on any joint. Equivalent to a two-joint link with all six DOFs fixed. |
| `area_sections` | Optional. Shell properties: `{"id": "SLAB200", "type": "shell-thin", "material": "C30", "thickness": 0.2}`. `type` is `shell-thin` (membrane + thin-plate bending), `shell-thick` (membrane + thick plate with transverse shear deformation) or `membrane` (in-plane only). A Membrane *floor* (sloped under 20 degrees) is meshed this way: cut at its beams and walls into convex panels of one element each, its vertical loads going to the beams (trapezoidal loads), walls and joints along the panel edges by tributary areas (rules in PHASE3B_PLAN.md, *2d continued*). `"one_way": true` (Membrane only): *Use special one-way load distribution* (Plank and Deck floors): the vertical loads go instead as strips along the area's local axis 1, half of each strip to each end, onto the beam, wall or free edge there (a free edge passes its share to its end joints); rules in ONE_WAY_LOAD.md, B56. The material needs `nu` (or `G`). |
| `areas` | Optional. Area objects (floors, walls): `{"id": "F1", "nodes": ["1", "2", "3", "4"], "section": "SLAB200", "angle": 0}`. Three or more corner joints, flat; only a 4-corner area may be warped (corners off one plane): it is not meshed and is analysed as one element on its mean plane, tied to its joints by rigid arms along the normal (twist above 30° gets a warning). A meshed area may be any polygon whose edges do not cross (L-shapes too); an area analysed as one element (its `"mesh": "none"`) needs 3 or 4 corners and must be convex. An area with `"mesh": "none"` and more than 4 corners in a meshed model is meshed with the model's settings, with a warning in the notes. Triangles are 3-node shells (see TRIANGLE_SHELL.md): area loads go q A/3 to each corner and forces are reported at the corners. Ids differ from frame and link ids. `angle` rotates local 1 and 2 about 3 (degrees). |
| `nodes[].label`, `frames[].label`, `links[].label`, `areas[].label` | Optional. The app's **labels** by plan position, the same on every story: a letter by the type (`J` joints, `C` / `B` / `D` frames by direction, `L` links, `F` / `W` areas by slope) and a number. The solver ignores them; the app brings them up to date when it opens a file and after every edit (rules in STORY_SYSTEM_PLAN.md, *Part B*). The app names new objects 1, 2… (joints), M1… (frames), K1… (links) and A1… (areas); any other ids work too. |
| `diaphragms`, `nodes[].diaphragm`, `areas[].diaphragm` | Optional. **Rigid diaphragms**: `"diaphragms": [{"id": "D1"}]`, then a joint or an area names one (`"diaphragm": "D1"`; an area's reaches all its joints, its mesh joints too). One constraint per diaphragm and story: its joints follow one master joint in UX, UY and RZ (u = u_m - θz (y - y_m), v = v_m + θz (x - x_m)) and keep their own UZ, RX and RY; exact, no stiff numbers. The master is the joint restrained in UX, UY or RZ (at most one per constraint), else the first in the file. A joint may not also be joined by a rigid link. A plane frame keeps UX tied at a level; in a plane grid diaphragms do nothing (a note says so). The mesh step keeps a joint of a rigid diaphragm as a mesh joint even with nothing attached (B50, B51); a semi-rigid one does not. `{"id": "D2", "semi_rigid": true}` is a **semi-rigid** diaphragm: it ties nothing (the floor's own in-plane stiffness acts) and only names the floor, for the centres of mass and user wind loads (below). The app makes a new model's D1 semi-rigid. |
| `masses` | Optional. Added joint masses in global axes: `{"node": "9", "ux": 2, "uy": 2, "uz": 2, "rx": 0, "ry": 0, "rz": 30}`; translations in mass units (force / (length / s²): t with kN and m), rotations as mass moments of inertia (mass · length²). Missing = 0. |
| `mass_source` | Optional. Mass source for the modal case: `{"elements": true, "joint_masses": true, "loads": [{"pattern": "SDL", "scale": 1}], "lateral_only": true, "lump_at_stories": true}` (missing fields, or the whole entry: these, the defaults, with no load patterns). **Element mass** = the structure's weight (material `weight` x A or thickness x the **mass** modifiers) / g (9.80665 m/s² in the model's length unit), lumped like self-weight: half of a frame object's mass to each of its own two ends (beams over their clear length; a frame the mesh step split still gives its mass to the object's ends), a shell element's to its corners like a uniform area load; no rotational inertia from elements. **Mass from load patterns** (`"loads": [{"pattern": "SDL", "scale": 1}]`; files without patterns name a load case instead, `{"case": "SDL"}`): downward load / g where it acts (an upward load takes mass off, horizontal loads none; frame loads to the object's ends by simple-beam statics; a Membrane floor's loads and self-weight at its elements' corners like element mass, not through the load transfer its static loads take), the pattern's self-weight included (a frame's half to each end of the object, like element mass). `lateral_only`: only UX, UY and RZ carry mass. `lump_at_stories` (with `stories`): the lateral mass of a joint between two levels is split between them linearly by height, each part to the nearest joint at that level (in plan, joined to it or not; of joints equally near, the first in node order; probe 10) (above the top level all of it to the top level); vertical mass stays. Rigid diaphragms carry their joints' mass to the master through the constraint (the floor's rotational inertia exactly, as a centre-of-mass point). |
| `modal` | Optional. A modal case, Eigen vectors: `{"id": "Modal", "modes": 12}` (missing fields: these), or **Ritz vectors**: `{"id": "Modal", "type": "ritz", "modes": 12, "starts": [{"accel": "UX"}, {"accel": "UY"}, {"pattern": "DEAD", "cycles": 2}]}`. The lowest `modes` eigenpairs of K φ = ω² M φ (fewer when the model has fewer independent mass DOFs; a note says so), by subspace iteration on the same stiffness as the static cases, with a Sturm sequence check that none is missed. Results in `modal` (below). Modal results are not part of load combinations. **Ritz**: each starting load (a ground acceleration `UX`, `UY`, `UZ`, or a ground rotation `RX`, `RY`, `RZ` about the centre of mass: its load is M r, each joint's masses times its rigid-body motion; or a load pattern's loads) gives one vector per cycle, the starts taking turns in their order until `modes` vectors: first K v = p, then K v = M q from its last vector q; each is made stiffness-orthogonal to the ones before (twice), and one left with at most 1e-6 of its stiffness norm adds nothing and stops its start. `cycles` limits a start's vectors (the static solve is cycle 1; missing or 0 = no limit). The modes come from the small problem Qᵀ M Q y = μ Qᵀ K Q y on the vectors: periods 2π√μ, shapes at unit modal mass; a load on joints without mass gives **static modes** (`"static_mode": true`, period 0, shape at unit stiffness, no mass), listed after the others and left out of spectrum cases. Fewer vectors than `modes` when the starts give no more (a note says so). Results also give `load_participation`: for UX, UY, UZ and each starting pattern, static % (the share of its static response's strain energy the modes reach) and dynamic % (of its part on joints with mass; an acceleration's is its cumulative mass ratio). |
| `p_delta` | Optional. **P-Delta**: `{"method": "loads", "loads": [{"pattern": "DEAD", "scale": 1}, {"pattern": "LIVE", "scale": 0.25}]}` or `{"method": "mass"}` (missing, or `"method": "none"`: none). Every case then uses a stiffness with a geometric stiffness added: load cases, the modal case (so spectrum cases) and combinations. **From loads** (`loads`: load patterns times factors, self-weight included; files without patterns name load cases, `{"case": "DEAD"}`): the P-Delta load is solved with P-Delta by constant-stiffness iterations (at most 10; when those run out or the unbalance grows, Newton steps from the start, at most 40) until the unbalance is below 1e-4 of the joint loads and the support reactions; each frame then has the consistent geometric stiffness of its mean axial force (its own bending shape functions, with shear deformation too; rigid end zones as bars carrying the force; releases condensed with it; a truss the string P / L), each shell that of its membrane forces on its three translations; rigid links none. A frame's moments along it carry its P-Delta axial force times its own deflection; its shear stays the applied side load. **From the mass**: every joint with mass (the mass source's) gets a spring -m g / z in UX and UY to the ground, z its height above the base level (the lowest story level; without stories the lowest joint); no axial forces; the springs count in the base reactions, not in the joint reactions. A structure that buckles under the P-Delta load gives a note and its results (a negative eigenvalue: negative period). B68-B70. |
| `on_instability` | Optional. What the analysis does when the structure has no stiffness in some direction (a part that is not held, a mechanism): `"continue"` (the default: a tiny stiffness, 1e-8 of the stiffness the joint's own elements give that direction, is put in each such direction and cut from the rest, the run goes on, and the directions are listed in `notes` and in the results' `instabilities`; results at and near them are not reliable) or `"stop"` (the analysis stops with the first such joint and direction). |
| `spectrum_functions` | Optional. Response spectrum functions: a table `{"id": "RS1", "damping": 0.05, "points": [[0, 0.32], [0.12, 0.8], [0.6, 0.8], [1.0, 0.48]]}` (period in s, value with no units; periods increasing; between points the value is linear in the period, before the first and after the last point constant), or the ASCE 7-16 design spectrum `{"id": "RS2", "asce7_16": {"ss": 0.8, "s1": 0.35, "tl": 8, "site_class": "D"}}` (Ss and S1 in g, TL in s, site class A-F; `fa` and `fv` replace the site coefficients and are needed for class F and where the code's tables ask for a site study): SDS = 2/3 Fa Ss, SD1 = 2/3 Fv S1, Fa and Fv from Tables 11.4-1 and 11.4-2 with straight lines between their columns; the curve of section 11.4.6 kept as points at T = 0, T0, TS and at 0.4-2 s every 0.2 s and 2.5-10 s every 0.5 s from the first such period more than 0.1 s above TS, with straight lines between them. `damping` (missing: 0.05) is the damping the function is given for. B63. |
| `pier_labels`, `spandrel_labels`, `frames[].pier`, `frames[].spandrel`, `areas[].pier`, `areas[].spandrel` | Optional. **Pier and spandrel labels**: `"pier_labels": [{"id": "P1", "color": "#c0392b"}]`, `"spandrel_labels": [{"id": "S1", "multi_story": true}]` (names unique; `color` for the app; `multi_story`, missing = false: one spandrel over every story); an object names one of each with `"pier": "P1"`, `"spandrel": "S1"` (not openings). A pier is the vertical walls (normal within sine 0.001 of horizontal) and vertical frames (ends within 0.001 m in plan) with one label at the story holding each one's highest joint; a spandrel the vertical walls and horizontal frames (ends within 0.001 m in height) with one label, a wall at the story level nearest its middle height (the base too), a frame at its story (and making a spandrel at the level nearest its middle only above the base); a multi-story label is one spandrel at the highest of those levels (the first story for the base). A spandrel needs its corners within 0.001 m of its first wall's plane. A label on another object is kept and left out (a note names it). The mesh step gives an area's label to its elements and a frame's to its pieces. Results: *Pier and spandrel forces* below. B67. |
| `groups` | Optional. Named sets of objects: `[{"id": "BEAMS", "color": "#3f8fd2", "nodes": [...], "frames": [...], "links": [...], "areas": [...]}]` (an object may be in several). Names must be unique and every object must exist; the analysis does not use them. |
| `not_run` | Optional. Cases set not to run: names of load cases, the modal case or spectrum cases, `["LIVE", "Modal"]`. They have no results, nor has any combination with a part that does not run (also through another combination). The modal case runs anyway while a spectrum case runs. Nothing left to run is an error. |
| `spectrum_cases` | Optional. Response spectrum cases on the modal case: `{"id": "RSX", "loads": [{"dir": "X", "function": "RS1", "scale": 9.80665, "angle": 0}], "damping": 0.05, "modal_combination": "cqc", "directional_combination": "srss", "abs_factor": 0.3, "eccentricity": 0.05}` (missing fields: these, but `abs_factor` 1 and `eccentricity` 0). ## Axes and signs (the common conventions of building analysis programs)
- Global Z is up.
- **End order:** end i is the end with the lower Z; at equal Z the lower X; at equal X the
  lower Y. Members given the other way round are reversed on load, keeping their meaning: `angle` changes
  sign and frame loads are mirrored (distances from the new end i, local 1 and 3 directions negated).
  The results list the reversed members in `notes` and show each element's `nodes` as analysed. Links follow the same rule (they have no angle or loads).
- **Local 1** runs from end i to end j.
- **Local 2**: for non-vertical members, in the vertical plane, pointing up. For vertical members, global +X.
- **Local 3** = 1 x 2 (horizontal). `angle` rotates 2 and 3 about 1 (counterclockwise when 1 points at you).
- **I33** resists bending about local 3 (for a beam with 2 up: the usual "major" bending). **I22** is about local 2.

Member internal forces, at a cut at distance x from end i:
- `P` axial (tension +), `V2`, `V3` shears, `T` torsion: forces on the positive-1 face, positive along +2/+3/+1.
- `M3`: positive compresses the +2 face. A beam with 2 up has **sagging = positive M3**.
- `M2`: positive compresses the +3 face.

**Areas (checked on 312 reference cases in `tests/area_axes_cases.json`):**
- Corners are analysed starting at the first corner (in the given order) at the lowest Z; the direction
  is kept. So an area given clockwise seen from above has local 3 pointing down.
- **Local 3** is the normal, pointing at you when corners 1-2-3 run counterclockwise (for a quad: the
  plane through the lines joining the midpoints of opposite sides).
- **Local 1** is horizontal: 1 = ref x 3 with ref = +Z, or +Y when 3 is within sine 0.001 of vertical.
  **Local 2** = 3 x 1 (pointing up for walls; +Y for a floor with 3 up, whose local 1 is +X).
- `angle` rotates 1 and 2 about 3, counterclockwise when +3 points at you.

Shell forces (per unit length, in the area's local axes):
- `F11`, `F22`: membrane forces on cuts normal to local 1 and 2, tension positive; `F12` in-plane shear.
- `M11`, `M22`, `M12`: bending and twisting moments; **positive moments give tension at the bottom**
  (the -3 face), so a floor with 3 up has sagging = positive (like M3 of a beam).
- `V13`, `V23`: transverse shears on cuts normal to local 1 and 2.

Reactions are the forces and moments the supports and springs apply to the structure, in global axes
(spring forces are reactions: on a spring DOF the value is -k u).

## Results file
The desktop app saves the results of the last run next to the model, in a folder `<name>.results`:
`index.json` (`version` 3; `model_hash`, a fingerprint of the model's analysis data with the `gui` part
left out, so the results are used again only when the model matches; `cases` and `modes`, how many),
`summary.json` (the results below with each case reduced to `id`, `combination`, `step`, `equilibrium` and
`has_shells`, the modal results without the modes' `shape` and with `joints`, the joints of every shape in
order, plus `geometry`: the objects every case has, in order: `displacements` and `reactions` (joint ids),
`frames` and `links` (`element`, `nodes`, `length`, `offsets`, `axes`), `shells` (`element`, `area`,
`nodes`, `axes`, `corners`: the joint of each corner)), `case-0.bin`, `case-1.bin`… in the summary's order
and `mode-0.bin`, `mode-1.bin`… in the modes' order. A case file is `OWB1` and four zero bytes, then 8-byte
little-endian floats in the geometry's order: UX..RZ of each joint, FX..MZ of each reaction, for each frame
and then each link its number of stations and each station's x, P, V2, V3, T, M2, M3, ux, uy, uz, then
F11..V23 of each shell corner; or `OWJ1`, four zero bytes and the case as JSON (a case whose objects differ
from the geometry). A mode file is `OWB1`, four zero bytes and UX..RZ of each of the modal `joints`, or
`OWJ1`, four zero bytes and the shape as JSON. Opening a model reads the index and the summary; a case's or a
mode's file is read when it is shown. Folders of an earlier version (2: shapes in the summary) are not read.

`osab solve model.json -o results.json` writes compact JSON (no spaces or line breaks), per load case and then per load combination
(`"combination": "<type>"`), each case as soon as it is known (one solve for all cases; the memory of a
few cases however many there are; `--only frames,reactions` writes only those parts of each case, of
`displacements`, `reactions`, `frames`, `links`, `shells`):
- node displacements (`ux .. rz`);
- reactions at supported nodes (`fx .. mz`, only for the DOFs the user restrained) and at nodes with springs
  (the spring forces, -k u);
- frame forces (`frames`: one entry per frame object, `element` holds its id; a frame the mesh step split
  has the stations of all its pieces, with both sides of every joint along it; `x, P, V2, V3, T, M2, M3`)
  at 11 equally spaced stations, plus two stations (just before
  and just after) at every point load inside the member, so diagrams show the jump and the peak. Station
  values are taken inside the member: at x = 0 just after end i, at x = L just before end j;
- the displacement of the member axis at each station (`ux, uy, uz`, global), including the deflection
  caused by frame loads and shear deformation, for drawing the deformed shape. It equals the node
  displacements of the same member split at its stations;
- `links`: the force in every rigid link, with the same fields as frames (`element` holds the link id;
  local axes by the member rule with angle 0, end order by the end-order rule; P, V2, V3, T are constant
  along a link, M2 and M3 linear). Links form trees, so each link's force follows from equilibrium of the
  part of the rigid body beyond it;
- `modal` (when the model has a modal case): `id`, `modes` (per mode: `mode`, `period` (s), `frequency`,
  `circular_frequency`, `eigenvalue` (ω²), `participation` (φᵀ M r, UX UY UZ RX RY RZ), `mass_ratio`
  (participating mass ratios, definition: (φᵀ M r)² / rᵀ M r over the free mass, rotations about
  the centre of all the mass), `sum_mass_ratio`, and `shape`: every joint's `ux .. rz` at unit modal
  mass (φᵀ M φ = 1 in the model's units; are at unit modal mass in N-mm), the largest translation
  positive), `masses` (the assembled joint masses after lumping), `free_mass` and `centre_of_mass`;
- `diaphragm_centers` (when the model has diaphragms): per story and diaphragm, the highest story first,
  `mass_x`, `mass_y` (the lateral masses of the diaphragm's joints there, after the mass source and
  lumping; a floor's mesh joints count), `xcm`, `ycm` (centre of mass: x weighted by the Y masses, y by the
  X masses), `cum_mass_x`, `cum_mass_y`, `xccm`, `yccm` (the same diaphragm at this story and every story
  above) and `xcr`, `ycr` (centre of rigidity: the point where a force on this diaphragm alone, the others
  free, moves it without turning it; 3D models). A semi-rigid diaphragm keeps its mass at its joints:
  masses and cumulative values 0, no cumulative centre and no centre of rigidity, and the centre of mass of
  its joints. B59;
- `mesh` (when the mesh step made anything): `joints` (mesh joints with coordinates), `shells` and
  `frames` (elements and frame pieces with their `parent` object and `nodes`), `edge_constraints`;
- `shells` (when there are areas): per shell element `element` and its `area` (the parent object),
  `nodes` as analysed, `axes` (local 1, 2, 3), and `corners`: `F11 F22 F12 M11 M22 M12 V13 V23` at each
  corner joint. Computed at the 2 x 2 Gauss points and extrapolated to
  the corners, not averaged with neighbouring elements. Checked on single elements and the shell benchmarks;
- each member's local axes as analysed (`axes`: unit vectors of local 1, 2 and 3 in global coordinates);
- `equilibrium`: `applied` and `reactions` resultants about the origin, `relative_error`
  (|applied + reactions| using support reactions and spring forces only) and `residual` (largest out-of-balance force at a
  free DOF). Both should be about 1e-8 or smaller.

**Load combinations** (checked in B26):
- A Linear Add of load cases and one-valued combinations has one value. It is solved as a linear static
  case with the scaled loads, so it has the same fields as a load case, including `equilibrium`.
- An Envelope or SRSS, or a Linear Add containing one, has a
  maximum and a minimum: two entries with the same `id` and `"step": "max"` / `"min"` (step
  type), no `equilibrium`. Values are combined one by one (each displacement, reaction, station force,
  shell corner force), so a maximum M3 and a maximum V2 may come from different cases. Envelope: largest
  and smallest of the scaled parts; Linear Add: max parts add up to the max (a negative factor turns a part's min
  into its max). SRSS: R = square root of the sum of the squared scaled parts, max = +R and min = -R (so the
  sign of a factor makes no difference); a part with a maximum and a minimum counts with the larger size of
  the two. Inside a Linear Add or an Envelope an SRSS counts as +R and -R. Frame stations are the union of
  the parts' stations.

**Spectrum cases** (checked in B63 and B64) come after the load cases, with `"spectrum": true`: every value
is a size (positive), worked out for each mode and combined over the modes and the loads on its own, so
values need not belong together (a maximum M3 and a maximum V2 may come from different modes). Frame
stations: equally spaced plus both sides of every load case's point loads (so each combination finds its
own stations among them). No `equilibrium`.

**Base reactions** (`base_reaction`, every case): FX FY FZ MX MY MZ, the sum of the support reactions and
spring forces about the origin; for a spectrum case each mode's sum, combined; for a combination's max or
min, value by value.

**Story results** (models with `stories`, every case): `joint_drifts`: per joint at a story level (mesh joints
left out) with a joint below it, at the same plan position on the level below or else the lower end of a
frame going down from it, `story`, `node`, `below` and `drift` X, Y = (u - u below) / the height between them,
signed (a spectrum case's are sizes); `story_drifts`: per story
and direction the largest joint drift by size (`drift`) and its `node`; `story_forces`: per story `top` (a
cut just below its level) and `bottom` (just above the level below), each P (up), VX, VY, T, MX, MY: the
forces the structure below the cut puts on the part above it, about (0, 0) at the level's height; an
element's own loads stay inside it (a wall's weight is all below the top cut, all above the bottom one). An
element counts only in the story holding its highest joint, and only at a cut whose level has one of its
joints: a column from the base to the second level gives the top of the second story and nothing else. A
frame the mesh step splits goes by its object in both tables: that column split at the first level still gives
only the top of the second story, and a joint partway along it has no frame going down from it.
In combinations they are combined like other values (the story drift of a step is the largest size of its
joint drifts). B64.

**Pier and spandrel forces** (models with labels, every case): `pier_forces`: per pier and story (the
highest story first) `story`, `pier`, `top`, `bottom`; `spandrel_forces`: `story`, `spandrel`, `left`,
`right`; each P, V2, V3, T, M2, M3: the sum of what the cut's joints put on the labelled elements on the
material side (frame end forces, shell joint forces less the element's own loads, the hidden beams of an
edge constraint and the frame-joint springs of a wall with its wall), about the cut's centroid, in the
section's axes, times +1 at the top and right, -1 at the bottom and left (P > 0 tension; M2 = minus the
moment about axis 2). A pier's cuts are horizontal at its lowest and highest joint, its axis 1 is +Z and 2
horizontal at its angle; a spandrel's cuts are vertical across its plan direction (the longest plan
distance between two of its corners or frame ends) at its ends, its axis 1 runs from the left centroid to
the right one, 2 is +Z; 3 = 1 x 2. A cut's centroid weighs its wall strips (length x thickness) and frames
(section area) by area; a spandrel cut touching only corners at one plan point is that point at height 0.
Joints above the highest story level give a spandrel nothing. A spectrum case's are sizes, combined over
the modes like other values (each mode's signed forces first); combinations combine them like other
values. `pier_sections` (top level): per pier `story`, `pier`, `angle` (local 2 from X, degrees),
`bottom`, `top` (centroids); `spandrel_sections`: `story`, `spandrel`, `left`, `right`. The rules and the
reference checks: docs/phases/PIER_SPANDREL_PLAN.md. B67.

`notes` lists automatic restraints, reversed members, springs that have no effect, badly shaped areas
(a corner angle outside 45-135 degrees or an aspect ratio above 4, common shell-element guidelines), and an accuracy warning when the stiffness matrix is
ill-conditioned (e.g. a very stiff member next to a very soft one). A pivot that loses about 12 of 16 digits
is treated as a direction without stiffness: by default it gets a tiny stiffness and the run goes on with a
warning in `notes`, and `instabilities` (top level, only then) lists each such `node` and `dof` with
`digits_lost`; with `"on_instability": "stop"` the analysis stops with the node and DOF. In the modal case
those directions are held (they do not move), so they make no modes of their own; a note says how many.
`failed` (top level, only then) lists a modal case that could not be analysed, `{"case": "Modal", "reason":
"..."}`: the other cases have their results, the response spectrum cases and the combinations that need it
are left out and named in `notes`. When the count that no mode was missed cannot be taken (every shift tried
lies on an eigenvalue), the modes are given with a warning in `notes`. When the eigenvalues stop getting
more exact before the tolerance (1e-12) is reached, because the stiffness has lost too many digits, the
iterations end there: the modes are given with a warning that says how exact they are when that is 1e-4 or
better, and the modal case fails otherwise.
